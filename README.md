# Практична 1-2

## Архітектура безпеки та реалізовані перевірки

В рамках проєкту було успішно інтегровано та налаштовано наступні етапи перевірки безпеки:

### 1. SAST (Статичний аналіз коду)
- **Інструменти:** `semgrep`, `bandit`, `pip-audit`.
- **Опис:** Автоматичне сканування вихідного коду під час кожного `push` у гілку `main`. Виявляє потенційні вразливості (зокрема SQL-ін'єкції та XSS) ще на етапі написання коду.
- **Процес:** Налаштовано правила тріажу результатів. Звіти сканування автоматично зберігаються як артефакти у GitHub Actions.

### 2. DAST (Динамічний аналіз)
- **Інструменти:** `OWASP ZAP` (ZAP Baseline Scan).
- **Опис:** Автоматизоване тестування розгорнутого застосунку в CI/CD конвеєрі. Локальне динамічне сканування Docker-контейнера успішно підтвердило наявність SQLi та XSS, а також виявило відсутність базових заголовків безпеки (CSP, Anti-CSRF токенів).

### 3. SCA та інспекція інфраструктури
- **Інструменти:** `Trivy`.
- **Опис:** Налаштовано окремий автоматичний процес (`trivy.yml`) для перевірки файлової системи, Docker-образів та залежностей (ОС та бібліотеки) на наявність відомих вразливостей (CVE).

### 4. Розширений захист GitHub
- **CodeQL:** Впроваджено семантичний аналіз коду за допомогою рушія GitHub CodeQL для глибокого пошуку логічних вразливостей.
- **Secret Scanning:** Увімкнено автоматичний захист від витоку секретів, API-токенів та паролів у репозиторій.

## Документація проєкту

Уся супровідна документація, звіти та регламенти знаходяться у директорії `docs/`:
- `threat-model.md` — початкова модель загроз.
- `sast-process.md` — опис процесу статичного аналізу та правила тріажу (обробки) знахідок.
- `dast-process.md` — висновки за результатами динамічного сканування застосунку.
- `audit-report.md` — підсумковий аудит безпеки, що включає перевірку виконання вимог, визначення ролей у процесі (Owner, Security Champion, Dev, QA, DevOps) та ітераційний беклог покращень.
